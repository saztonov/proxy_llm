# Агентский контур: OpenAI API для AI-агентов сотрудников

Для кого: сотрудники, которые подключают Cursor, Continue, Cline, Aider или OpenAI SDK, и администратор (раздел «Для администратора» в конце).

## Что это

| | |
|---|---|
| Адрес (base URL) | `https://<домен прокси>/agent/v1` — точный адрес показывается в админке при выпуске ключа |
| Ключ | `pl_agent_…` — выдаёт администратор на отдел или на сотрудника; показывается один раз |
| Модель | назначает администратор; любое имя модели в запросе заменяется назначенной |
| Поддерживается | `POST /chat/completions` (обычный и `stream: true`), `tools` / `tool_choice`, `response_format`, `GET /models` |
| Не поддерживается | `/embeddings`, `/completions` (legacy), `/responses` (Codex CLI), Anthropic Messages API |

В `GET /models` видны две модели: реально назначенная и алиас `default`. Указывайте `default` — тогда смена модели администратором не потребует менять настройки IDE.

Параметры, которые назначенная модель не поддерживает (например, особые режимы reasoning другой модели), вернут ошибку 400 от провайдера — её текст показывается как есть.

## Cursor

1. Settings → Models → **OpenAI API Key**: вставьте ключ `pl_agent_…`.
2. Включите **Override OpenAI Base URL** и укажите адрес `https://<домен прокси>/agent/v1`.
3. Добавьте модель с именем `default` (подойдёт любое имя) и нажмите **Verify**.

Ограничения BYOK в Cursor, которые от прокси не зависят: Tab-автодополнение и часть встроенных функций работают только на моделях самого Cursor; запросы идут через серверы Cursor, и ключ передаётся им.

## Continue

```yaml
models:
  - name: Company LLM
    provider: openai
    model: default
    apiBase: https://<домен прокси>/agent/v1
    apiKey: pl_agent_...
```

## Cline

API Provider: **OpenAI Compatible**; Base URL: `https://<домен прокси>/agent/v1`; API Key: ключ; Model ID: `default`.

## Aider

```bash
export OPENAI_API_BASE=https://<домен прокси>/agent/v1
export OPENAI_API_KEY=pl_agent_...
aider --model openai/default
```

## OpenAI SDK

```python
from openai import OpenAI
client = OpenAI(base_url="https://<домен прокси>/agent/v1", api_key=os.environ["PROXY_AGENT_KEY"])
for chunk in client.chat.completions.create(model="default", stream=True,
                                             messages=[{"role": "user", "content": "Привет"}]):
    print(chunk.choices[0].delta.content or "", end="")
```

```ts
import OpenAI from 'openai';
const client = new OpenAI({ baseURL: 'https://<домен прокси>/agent/v1', apiKey: process.env.PROXY_AGENT_KEY });
const r = await client.chat.completions.create({ model: 'default', messages: [{ role: 'user', content: 'Привет' }] });
```

## Ошибки

| Код | `error.code` | Что значит | Что делать |
|---|---|---|---|
| 401 | `invalid_api_key` | ключ неверен, отозван, истёк или его владелец отключён | попросить новый ключ |
| 403 | `ip_not_allowed` | ключ ограничен сетями, запрос пришёл из другой | работать из разрешённой сети |
| 429 | `rate_limit_exceeded` | превышена частота запросов владельца ключа | подождать `Retry-After` |
| 429 | `too_many_parallel_requests` | слишком много параллельных запросов владельца ключа | дождаться завершения текущих |
| 503 | `server_overloaded` | прокси загружен целиком | повторить через несколько секунд |
| 503 | `agent_not_configured` | ключу не назначена модель или её провайдер выключен | к администратору |
| 502 | `upstream_auth_failed`, `upstream_payment_required` | проблема аккаунта провайдера у прокси | к администратору |
| 504 | `deadline_exceeded`, `first_event_timeout` | провайдер не ответил вовремя | повторить |

Если ошибка случилась, когда ответ уже стримится, она приходит последним событием потока: `data: {"error":{"code":"stream_idle_timeout",...}}` (провайдер замолчал) или `stream_incomplete` (поток оборвался до конца, ответ может быть неполным). SDK поднимает обычное исключение.

## Для администратора

**Где что настраивается** — `/admin`:
- «Провайдеры» — OpenAI-совместимые провайдеры: base URL до версии API включительно (`https://openrouter.ai/api/v1`, `https://api.openai.com/v1`), ключ, дополнительные заголовки, лимит одновременных запросов. Кнопка «Проверить» делает `GET /models` с ключом; для OpenRouter ключ дополнительно проверяется `GET /key`.
- «Настройки» — глобальная модель по умолчанию (провайдер + модель) и дефолтные лимиты владельца ключа.
- «Справочник» — отделы и сотрудники; лимиты можно задать отделу или сотруднику. Отключение отдела или сотрудника гасит его ключи сразу, без отзыва.
- «Агентские ключи» — выпуск на отдел или сотрудника, своя модель ключа (иначе — глобальная), срок действия, разрешённые сети, отзыв.
- «Статистика» — расход по отделам, сотрудникам, ключам, провайдерам и моделям.

**Ёмкость по умолчанию.** Рассчитано на несколько десятков одновременных пользователей:

| Параметр | Значение | Переменная |
|---|---|---|
| одновременных запросов к провайдерам на весь контур | 32 | `AGENT_QUEUE_CONCURRENCY` |
| принятых запросов всего (в работе + очередь) | 64 | `AGENT_QUEUE_MAX_PENDING` |
| на владельца ключа: в работе + в очереди | 3 + 3 | `AGENT_PRINCIPAL_MAX_*` или лимиты в справочнике |
| запросов в минуту на владельца ключа | 240 | `AGENT_RATE_LIMIT_MAX` |
| тело запроса | 1 МиБ | `AGENT_BODY_LIMIT_BYTES` |

Лимиты считаются на владельца, а не на ключ: второй ключ того же сотрудника не удваивает его долю. Ключом отдела, которым пользуются N человек, лучше не делиться — выдайте людям личные ключи, либо поднимите лимиты отдела примерно до 2×N.

**Учёт.** Для провайдера OpenRouter стоимость фактическая (`usage.cost` из ответа, в стриме — из последнего чанка). У других провайдеров пишутся только токены: стоимость остаётся неизвестной, прокси её не придумывает. Прерванный пользователем стрим часто не несёт usage — такая попытка видна в отчётах как «без стоимости».

**Безопасность.** В nginx `location /agent/` без IP-allowlist: Cursor ходит со своих облачных серверов. Защита — 128-битный ключ, лимиты владельца, срок действия и сети на ключ, алерт в Telegram на всплеск неверных ключей. fail2ban по IP для `/agent/` не вешать: бан общего IP Cursor отключит всех сотрудников сразу.

**Без веба (CLI).** Всё основное доступно из `dist/cli/admin.js` (`provider add`, `department add`, `employee add`, `agent-token issue`, `settings set-default`). Работающий сервис видит изменения после `systemctl kill -s HUP proxy_llm`. Секреты передаются только через stdin.

**Нагрузочная проверка.** `scripts/load-agent.mjs` запускает N параллельных стримов; ключи — по одному на строку в файле (разные владельцы, иначе упрётесь в лимит владельца):

```bash
node scripts/load-agent.mjs --base https://<домен прокси>/agent/v1 --tokens temp/agent-tokens.txt --parallel 40
```

Результат — коды ответов, время до первого байта (p50/p95) и длительность. После прогона сверьте RSS процесса (`systemctl status proxy_llm`) с `MemoryMax`.
